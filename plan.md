Resolved the Admin Content and Packages `500 Internal Server Error` without resetting or replacing the shared PostgreSQL database. The pre-existing no-op migration `20260831000000_decouple_question_bank_commerce` was restored to local migration history with its original empty `migration.sql`, then the pending additive migration was applied using `prisma migrate deploy` and Prisma Client was regenerated. Prisma now recognizes all 42 migrations and reports the schema up to date.

Verified the repaired paths through the real database: the public catalogue returns HTTP 200, the Admin package service returns the existing package total, and the Admin content service successfully reads the selected course. Server and website typechecks pass, the backend and website production builds pass, and the focused resource-validity/security suites pass 8/8. No records were dropped, reset, truncated or reseeded.

Removed the conflicting `aria-hidden` attribute from the responsive Super Admin and Academy Admin navigation drawers while retaining their existing `inert` behavior. This prevents a focused navigation link from being hidden from assistive technology and clears the browser accessibility warning without changing the approved UI, routes or navigation behavior.

## First-class Question Bank production completion — 30 August 2026

The latest approved architecture is now implemented end to end. `QuestionBank` is a product/container; Excel is only an import mechanism; `Question` is an individual normalized record; `QuestionContentLink` supplies content/taxonomy access context; website Purchase produces Entitlement; and Entitlement determines whether a learner may access a paid bank. This checkpoint supersedes every older historical statement that defines Question Banks only as PDF notes/packages or says all Practice questions are universally free.

Prisma now contains tenant/course-scoped Question Banks, a direct nullable `Question.questionBankId` owner relation and persisted `PracticeSession.questionBankId`. A Question belongs to at most one bank; placing identical wording in another bank creates a separate Question record. `QuestionContentLink` remains the independent many-to-many file/access relation. Admin, Super Admin and Academy Admin use the existing Questions workspace and RBAC/tenant patterns to create, inspect, edit, publish, archive, restore, safely delete an empty draft, and populate Normal-MCQ or Case-MCQ banks manually or through exact server-generated Excel templates. Case imports include `Correct Explanation`, validate all rows and linked files before an atomic commit, and persist both correct and wrong-option explanations.

Student discovery, filtering, preview, session creation, question delivery, attempts and results enforce selected course, publication, tenant isolation, linked-file OR authorization and exact entitlement. Free published banks remain available inside the selected course; paid banks require the exact active direct-content/package entitlement. Wrong Answers remains derived from persisted attempts, and weak-area/study-plan intelligence consumes normalized private concept metadata without exposing it in learner question payloads.

During final integration verification, a shared catalogue defect was corrected: PostgreSQL's `NULL` semantics caused ordinary Content Items with `entityType = NULL` to be accidentally excluded by a `NOT MONTHLY_REPORT` predicate. The predicate now explicitly permits `NULL` while continuing to exclude Monthly Reports. This restores ordinary PDF/image authorization for Notes and Practice without weakening report isolation.

Additive migrations `20260830153000_add_first_class_question_banks` and `20260830193000_enforce_single_question_bank_ownership` are applied. Prisma reports 40 migrations and the schema up to date. Final verification after the direct-owner lifecycle audit: server, website and mobile TypeScript pass; Prisma validate/generate pass; server and website production builds pass; and all 69 active server tests pass. The isolated real-PostgreSQL Question Bank flow covers tenant, type, file, purchase, entitlement, Excel-import and Student Practice boundaries. No reset, truncate, drop or destructive seed was used.

## Persistent handoff context

### Authoritative Practice Studio model — 29 August 2026

This section supersedes every older Practice/Question Bank statement later in this historical plan.

- The finalized Practice Studio has exactly four learner modes: MCQ, Case Study, Question Bank and Wrong Answers. Solve & Earn and descriptive evaluation are out of scope.
- MCQ and Case Study use published Admin-authored questions linked to one or more course content files. A question is visible when the learner can currently access at least one linked file; multiple links use OR semantics.
- Question Bank practice is a distinct `QUESTION_BANK` collection authored by Admin against paid course files. It is available only through an active direct-content or package entitlement, including files nested beneath an entitled package folder. A broad course entitlement alone cannot unlock a bank.
- Purchased PDF question-bank notes/packages still appear in Notes/Library. Practice Question Bank records are separate questions, but reuse the same package/content entitlement and purchase system.
- Wrong Answers is derived from persisted incorrect attempts and only returns missed questions that remain authorized now. Revoked, expired, foreign-course and foreign-tenant content is excluded.
- Free/Paid policy controls retry/explanation behavior and advanced weak-topic analytics. Selection, count, timer, evaluation, attempts and results are server-authoritative.
- `mobile/` contains the Expo learner app. `Parallax-Flow-web/` contains the shared Admin/Store React app and Express/Prisma/PostgreSQL API. Shared-backend changes must remain additive and tenant-safe.

### Authoritative Practice and Question Bank model — 26 August 2026

- Practice questions are completely free and come from published Admin Excel/question uploads for the learner's selected course.
- Practice has no Solve & Earn mode and no Question Bank/package entitlement source.
- Purchased “Question Banks” are PDF notes/packages; they appear in Notes/Library and use protected-reader entitlements.
- Free/Paid status affects Practice retry, explanation and advanced weak-topic analytics only—not question visibility.
- Student backend and both real/demo mobile Practice UIs were corrected accordingly. Admin-owned UI/routes were not edited.

This repository contains the existing Parallax Flow web product in `client/` and its API in `server/`. The current task is to recreate the web UI as a React Native application, preserving real MVP behavior and the product visual identity rather than making a generic course app.

The mobile app will live in a new sibling folder, `mobile/`, so the existing Vite web client remains untouched and can continue to serve as the visual and behavior reference. It uses Expo, TypeScript, Expo Router, TanStack Query, Zustand, and React Native primitives. **The current delivery is UI-only:** local mock data and tappable prototype flows are used while visual design is reviewed. Server API, secure token storage, payments, realtime sessions, and other backend integration are intentionally deferred until UI approval.

### Existing product understood

- **Brand:** Parallax Flow; disciplined, calm, premium exam preparation. Deep navy `#252B69`, indigo `#4654A3`, warm gold `#B38A4A`, Manrope typography, intentional light and dark themes.
- **Student areas:** authentication; Home/Dashboard; Notes (exam → stage → recursive subjects → lessons); secure lesson viewer; Practice; Tracker; Library/orders/receipts; Account.
- **Student navigation:** mobile bottom tabs for Home, Notes, Practice, Tracker, and Library; account is reached from the top bar.
- **Core states:** free/paid/owned/locked lessons, completion/revisions, study check-in/out, countdown/targets/streaks, MCQ and written grading, purchase/coupon/payment states, immutable receipts, loading/empty/error/recovery states, displaced-session handling.
- **Admin:** separate administrative login and content, packages, coupons, questions, settings/broadcast, audit, students, and order workflows. It is desktop-first on the web; a native implementation will make operational screens usable on phone/tablet without inventing unsupported features.
- **Future server compatibility:** the existing client uses an authenticated Axios API client, Bearer access tokens, refresh endpoint, and socket-based single-device-session notification. Those contracts will be addressed only after the UI is finalised.

### Constraints and decisions

- Do not modify or replace `client/`; it is the source of truth for UI and interactions.
- Do not invent features excluded by the existing MVP, including video learning, chat, social feeds, raw secure-PDF downloads, annotations, certificates, or an AI tutor.
- Build in verified vertical slices. Each completed phase updates this file with concrete files, verification, and any decisions made, so another agent can resume without rediscovery.
- UI review must not require the backend. Each screen uses local, realistic Parallax Flow mock content and state transitions; mock data will later be replaced behind a stable UI-facing data boundary.
- Recreate native equivalents; web-only primitives such as DOM/CSS, browser local storage, HTML tables, and browser PDF/canvas cannot be copied verbatim.
- Final platform verification requires a JavaScript runtime/dependencies and, ideally, an Android/iOS emulator or device.
